Application layer

This layer is the message your program understands. The six names in the box are the ones to memorize. Long polling, HLS, and DASH sit here too, and they ride HTTP.

For a normal API, say HTTPS with REST. Say Server-Sent Events when only the server pushes. Say WebSocket when both sides send. Say gRPC between your services. Say HLS or DASH for stored video. Say WebRTC for a live call.

HTTP / HTTP/2

Most common use. A public web request. Use HTTPS for a public site. HTTP/2 carries many calls on one connection, and it carries gRPC.

HTTP carries REST, GraphQL, long polling, Server-Sent Events, WebSocket setup, HLS, and DASH. HTTP/2 carries gRPC. One call ends when the response arrives.

TLS / DTLS

Most common use. TLS encrypts a public HTTP call. That pair is HTTPS. DTLS encrypts WebRTC media on UDP.

TLS encrypts bytes on TCP. HTTPS is HTTP inside TLS. DTLS encrypts bytes on UDP. WebRTC media uses DTLS.

Round trip time is the wait for a packet to go and come back. A new HTTPS connection spends one round trip on TCP and one round trip on TLS.

Ready.

TCP and UDP

Most common use. TCP carries almost every call. UDP carries live audio, a game, or a DNS lookup, when a lost packet is acceptable. A browser reaches UDP through WebRTC.

TCP and UDP are the transport. TCP keeps order and sends a lost packet again. UDP sends the packet and moves on. IP is the next layer under both.

IP

Most common use. Name a machine and route the packet. In an interview, this layer means IP. A far user waits longer. A CDN stores images and video near that user.

IP carries the packet from one address to another. The application message stays inside the upper layers. Distance on this path sets the round trip.

Where a balancer sits

A balancer sits beside one layer. The client-side balancer runs in the client, before the stack. An L7 balancer reads HTTP. An L4 balancer reads TCP and the IP address.

Client-side balancer

Most common use. Internal services you control, such as gRPC. DNS is the common form when many public clients can accept a slow update.

A config file holds only a seed. The seed is the address of the registry. The program fetches the server list. The program keeps that list in memory.

This page is that program. The list comes from GET /api/registry. The variable clientCursor walks server-a, then server-b, then server-c. Close the tab and the list is gone until the next click.

A phone browser for a public site uses DNS. The phone asks for a name. DNS returns an address. The phone caches that address for the TTL. TTL is the time the answer stays valid. The phone then talks to a dedicated balancer.

A phone app you ship can keep the list in app memory. The app starts from a seed address. The app refreshes the list from the registry.

When a call fails

These tools sit on the call. They work at the layer that waits for an answer. A timeout bounds one try. An idempotency key makes a retry safe. A circuit breaker stops a stream of tries.

Timeout and backoff

Most common use. A call that fails for a moment. In an interview, say retry with exponential backoff, and add jitter.

A timeout stops a slow call. A retry sends it again. Exponential backoff waits longer after each failure. Jitter is a small random extra wait, so many clients do not retry together.

Idempotency

Most common use. A payment, or any write the client might send twice. A GET is already safe to repeat.

A retry can charge a card twice. The idempotency key is a name for one charge. The server stores the first receipt and returns it on the next call with that key.

Circuit breaker

Most common use. A dependency stays down. Stop the calls to an external API, a database, or another service.

The breaker counts failures. After three failures it opens. An open breaker fails fast and does not call the dependency. After a short wait it becomes half-open and allows one trial. A success closes it.
