Data modeling

Interview default. Use Postgres for users, posts, and likes. Keep the author name on the user row. Add an index on (user_id, created_at) for recent posts of one user. Copy a field only when that read is hot.

The functions live in src/main.py and src/engines.py. Each button prints the picture, then the JSON.

Relational / row-oriented

Interview

Say PostgreSQL when rows point at each other and a write must stay correct.

Requirement

You need a unique phone, a foreign key, or a payment that happens once.

Industry databases

PostgreSQL, MySQL, Oracle, SQL Server. This tab runs PostgreSQL.

Storage

The whole account sits in one row. An index on phone finds that row.

Data shape

Write

INSERT INTO accounts (id, username, phone) VALUES (2, 'bob', '555-0101');

Read

SELECT id, username, phone FROM accounts;

Wide-column

Interview

Say Cassandra when one chat id owns a time-ordered list of messages.

Requirement

The hot read is the messages in one conversation, in time order.

Industry databases

Cassandra, ScyllaDB, HBase. This tab runs Cassandra.

Storage

Messages for one chat sit in one partition. Time sorts the rows inside it.

Data shape

Write

INSERT INTO messages (chat_id, sent_at, sender, body) VALUES ('chat-1', '2024-01-01 10:05:00', 'ada', 'on my way');

Read

SELECT sender, body FROM messages WHERE chat_id = 'chat-1';

Columnar analytics

Interview

Say a columnar store when a report sums one column across many rows.

Requirement

The screen is messages per city per day. The send path stays on the message store.

Industry databases

Snowflake, BigQuery, ClickHouse, Redshift, DuckDB. This tab runs ClickHouse.

Storage

Each column sits together. A sum reads the messages column.

Data shape

Write

INSERT INTO message_stats VALUES ('2024-01-01', 'Guangzhou', 400);

Read

SELECT city, sum(messages) FROM message_stats WHERE day = '2024-01-01' GROUP BY city;
Open this tab to read ClickHouse.

Graph

Interview

Say a graph store when the product is a hop from friend to friend.

Requirement

The main screen walks friend edges. A short hop can stay in PostgreSQL.

Industry databases

Neo4j, Amazon Neptune, JanusGraph. This tab runs Neo4j.

Storage

A person is a node. FRIEND is an edge stored with those nodes.

Data shape

Write

MERGE (ada:Person {name:'ada'}) MERGE (lee:Person {name:'lee'}) MERGE (ada)-[:FRIEND]->(lee);

Read

MATCH (ada)-[:FRIEND]->(friend)-[:FRIEND]->(next) RETURN next;
Open this tab to read Neo4j.

Time-series

Interview

Say a time-series store when every row is a time and a measurement.

Requirement

The question is how many messages a room sends each minute.

Industry databases

InfluxDB, TimescaleDB, Prometheus. This tab runs TimescaleDB.

Storage

Rows sit in time chunks. A chunk is one time range of the same table.

Data shape

Write

INSERT INTO msg_rate (time, room, messages) VALUES ('2024-01-01 10:03:00+00', 'chat-1', 15);

Read

SELECT time, messages FROM msg_rate WHERE room = 'chat-1' ORDER BY time;
Open this tab to read TimescaleDB.

Copied author name

Most common use. Keep the name on the user. Copy it onto each post only for a hot read.

Ada has two posts. A rename writes users.username. The join sees the new name. post_copies stays old until you update each copy. rename_user does that write.

Click a button.

Likes

Most common use. One Postgres row per user and post. Redis holds a count when that number is hot and a short lag is acceptable.

Bob already likes post 1. A second Postgres insert returns the first row. A Redis member key increments once. A bare counter increments on every click. record_like runs each path.

Click a button.

Partition key

Most common use. Recent posts of one user use user_id. Shard by that key only after one Postgres is full. The index comes first.

Nova is user 7. All of her posts sit on one shard. Salt spreads those posts, and the read merges the shards. Four app servers still call that one shard. A read replica can serve the read. partition_map draws the map.

Click the button.

Home feed

Most common use. Build the home feed when the screen is "posts by people I follow." That query is not user_id of one author.

Bob follows Ada and Nova. A read asks both author shards and merges. An inbox copies each post onto Bob at write time, so his screen is one query. home_feed shows both.

Click the button.

Graph hops

Most common use. Store follows as rows in Postgres. Two joins answer a friend of a friend.

Ada follows Bob. Bob follows Nova. graph_hops walks those edges in Postgres. The Graph button above reads the same hop from Neo4j.

Click the button.
