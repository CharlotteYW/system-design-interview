Which method should I choose?

Start with the query you need and the store you already operate. Compare the costs on your geographic data.

MethodUseful whenWhat you maintain
Full scanYou have a small fixture or need a reference result.Business rows. Each search checks every point.
PostGIS / R-tree familyYou need radius queries and profiles in a relational catalog. This is our interview default.PostGIS and a GiST index on location. PostgreSQL maintains it on writes.
GeohashYou want rectangular cell keys in a store with ordinary key lookups.A generated key and B-tree in this lab. Search covers adjacent cells and checks distance.
QuadtreeRegional point searches benefit from smaller subdivisions where points cluster.A tree, a leaf target, and a depth limit. A production service would maintain or rebuild the tree across requests.
k-d treeYou have a mostly static point set and need coordinate range or nearest-point lookups.A tree that splits one coordinate at a time. Updates need a rebuild or balance policy.
BKDYou already use a search engine such as Lucene for text and geographic filters.Search index segments, refresh and merge work, and a way to copy catalog changes. Design comparison.
Google S2You want spherical region covers and the option to read descendant ID ranges.S2 cell IDs and ordered lookups. The lab stores them in the shared lookup table.
H3You need neighbor relationships or want to count points by geographic cell.H3 cell IDs and overlap rules. For a radius query, check actual distance after cell lookup.
