Variants on this page

  

    
Presigned multipart (default)

    
The browser cuts the file into 5 MiB parts, asks the API for one signed URL per part, and PUTs each part to S3.
      Each part carries x-amz-checksum-sha256, so S3 rejects a damaged part. S3 returns an ETag per part, the receipt.

    
Resume through ListParts

    
"Forget receipts and resume" throws away the browser's ETags, then asks GET /v1/videos/{id}/upload.
      The service calls S3 ListParts and returns every stored part with its ETag, so only missing parts are sent.

    
S3 event vs service trigger

    
Default: the S3 ObjectCreated event starts the job, so a crash after S3 completes still processes the file.
      Service trigger: the service queues the job; if it crashes first, the video stays processing until the sweep.
      Replaying the event shows the job start is idempotent: starts_seen grows, no second job.

    
Chunk × rendition tasks

    
The plan step checks the SHA-256, splits at keyframes into 4 s chunks, then queues one task per chunk per rendition.
      240p tasks go on the high-priority queue, so the video is ready to play before 720p is done.

    
Worker crash

    
The next worker that leases a task exits mid-task. Its 8 s lease expires, the reaper requeues the task,
      and another worker writes the same segment key. The cell shows attempt 2.

    
CDN, slow edge, no shield, origin

    
The edge returns X-Edge-Cache (MISS then HIT). The slow edge limits bandwidth so adaptive bitrate picks 240p.
      Origin direct skips the CDN, which works for one viewer and not for 1 Tbps.
